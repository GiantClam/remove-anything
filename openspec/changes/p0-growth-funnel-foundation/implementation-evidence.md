## Local verification

Final local validation on 2026-10-15 (Asia/Shanghai): `pnpm test` — **206/206 passed**, exit 0; the focused `object-step-input-safety.test.ts` passed 3/3; `pnpm exec tsc --noEmit --pretty false --incremental false` — exit 0; `pnpm lint` — exit 0 with existing warnings only; `SKIP_DB_BUILD=1 pnpm build` — exit 0; `openspec validate p0-growth-funnel-foundation --strict --no-interactive` — valid, 0 issues; `git diff --check` — exit 0; Prettier checks for changed scripts, watcher/retention/migration files — passed. The focused canonical-smoke and weekly-report suites passed 10/10, and the weekly report command exported `NO DATA` without inventing traffic or revenue. These are local checks against fakes and fixtures, not production acceptance.

The local production build was started with `HOSTNAME=localhost` because Next 14 normalizes loopback requests to `localhost` before strict origin comparison; using `127.0.0.1` causes a self-proxy redirect loop in the standalone server. Against that build, `node scripts/verify-seo.mjs http://localhost:3000` passed and `SMOKE_BASE_URL=http://localhost:3000 SMOKE_GA_ID=G-VD6F0YDBQ5 pnpm test:smoke` passed all six canonical pages, sitemap-index children, and the exact GA loader URL. The HTTP check only proves the afterInteractive loader is scheduled; it does not prove hydration or external receipt.

With Google Analytics and Tag Manager requests blocked before navigation, a browser check of the same local production build found all six pages at HTTP 200 with `#google-analytics`, `window.gtag`, and an exact `gtag('config', 'G-VD6F0YDBQ5', { send_page_view: false })` entry. This is local initialization evidence only; no GA request or DebugView/realtime receipt was allowed.

The retention execution route is now fail-closed: `TASK_RETENTION_EXECUTE=true` returns HTTP 503 (`RETENTION_EXECUTION_BLOCKED`) before storage/database access until cleanup claims coordinate with all reference creators and task/status writers. A pure in-memory race probe reproduced a shared-reference addition plus expiry/status change after the pre-delete count; the old runner deleted the object and updated by ID. Dry-run remains available and the execution path is not a release gate that can be enabled by an environment flag alone.

The migration audit added `migration-runbook.md`, aligned the checked-in SQL and Prisma `timestamp(3)` precision/index names, and confirmed that the current Prisma, Drizzle, and Wrangler commands do not automatically apply the three SQL files. No real migration was executed.

Fresh read-only production checks on 2026-10-15 still fail at the deployed site: `pnpm test:smoke` exits 1 because `https://www.remove-anything.com/remove-objects` has no JSON-LD, and `node scripts/verify-seo.mjs https://www.remove-anything.com` exits 1 because the deployed `/sitemap-tools.xml` omits `/remove-objects`. The six pages otherwise returned HTTP 200 with canonical and H1 checks. The working-tree fixes are not deployed, so these are open release blockers.

Browser rendered-page evidence: `output/playwright/p0-browser/canonical-final-evidence.json`, `summary.json`, and the adjacent screenshots. All 12 rendered pages passed the six-tool English/existing-`zh-tw` checks; this does not represent new localization work. Local development runs on port 3100 while canonical URLs use the configured application origin `http://localhost:3000`; canonical paths were checked independently of that host difference. Watermark contracts were refreshed after the single-file and 40MP safety changes.

`output/playwright/p0-browser/watermark-flow-evidence.json` records a mocked queued → success → ZIP download → 410 expired-error flow, including the principal cookie on status reads and a successful download. Development `useAuth` still injects `DEV_USER` even when the auth endpoint is mocked empty, so this is UI evidence, not proof of production anonymous authentication. The real route tests separately exercise signed-principal access. There were no page/hydration errors; blocked Google analytics requests and the intentional 410 do not establish production GA4 delivery. The browser run also exposed and fixed the missing marketing `History` translation namespace used by the download action.

Build/browser checks use `SKIP_DB_BUILD=1` to avoid build-time database reads. This does not validate database connectivity or deployed migrations. Lint warnings, external font fallback, blocked local GA/GTM requests, and the development-auth boundary must be retained with the command results.

2. Complete input safety for composition and enforce declared processing timeout/concurrency rules across all core tools. Detect/segment input checks are locally covered, but still need production rollout evidence.
3. Verify provider-source allowlists, callback-secret delivery, composition authorization and private storage policy; reconcile historical public URLs, then validate the six complete real upload/result/error/retry/download flows.
4. Apply/rehearse `0002_task_lifecycle.sql`, `0003_authorization_audit.sql`, and `0004_task_retention.sql`; validate real serializable reservations, callbacks, credit/payment reconciliation and rollback.
5. Fulfill physical source/result deletion and 90-day minimal audit retention for all storage/provider/task paths. Review dry-run blockers before enabling bounded execution; see `retention-runbook.md`.
6. Complete the behavioral event chain, durable server delivery and weekly slices/reliability reporting; attach production GA4 DebugView/realtime, GSC, deployed SEO, purchase and audit evidence.
7. Start the 28-day baseline only after those gates pass. Require three pages with real GSC impressions, stable completion/download baselines, and an attributable registration/purchase/lead before P1 expansion.
8. Redeploy and re-run production SEO smoke: the current deployment still lacks `/remove-objects` JSON-LD and its tools sitemap entry even though the local build passes.
